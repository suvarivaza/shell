# Server Setup

Документация для интерактивного скрипта [`server_setup.sh`](server_setup.sh).

## Назначение

`server_setup.sh` предназначен для первичной настройки и последующей проверки Linux-сервера. Скрипт объединяет операции с SSH, Fail2Ban, Nginx, пользователями, сетью и `iptables`.

Название `Server Setup` оставлено намеренно: безопасность является основной частью скрипта, но он также содержит общую диагностику и административные операции.

## Поддерживаемое окружение

Скрипт рассчитан прежде всего на Debian и Ubuntu с:

- `systemd`;
- OpenSSH Server;
- `sudo`;
- `iptables` и `ip6tables`;
- пакетным менеджером APT;
- Nginx и Fail2Ban для соответствующих разделов меню.

Часть диагностических функций будет работать и без Nginx или Fail2Ban. Установка Fail2Ban и `iptables-persistent` использует APT, поэтому на системах другого семейства эти операции выполнять нельзя.

## Запуск

```bash
chmod +x server_setup.sh
./server_setup.sh
```

Запускать весь скрипт от `root` необязательно: команды, которым нужны повышенные права, используют `sudo`.

Не рекомендуется запускать скрипт напрямую из непроверенного удалённого URL. Сначала сохраните файл локально, проверьте его содержимое и только после этого запускайте.

## Резервные копии

Перед изменением критичных конфигураций скрипт сохраняет резервные копии в:

```text
/root/server-setup-backups
```

В этот каталог попадают:

- предыдущая конфигурация SSH, созданная скриптом;
- предыдущая конфигурация Fail2Ban, созданная скриптом;
- полные активные правила IPv4 и IPv6 перед изменением `iptables`;
- содержимое `ipset`, если утилита установлена.

Резервные копии не удаляются автоматически.

## Рекомендуемый порядок первичной настройки

1. Запустить пункт **«Аудит безопасности без изменений»** и сохранить результат.
2. Проверить, что вход по SSH-ключу действительно работает во второй терминальной сессии.
3. Отключить парольный вход через раздел **SSH**.
4. Установить и настроить Fail2Ban.
5. Ограничить доступ к ISPmanager разрешёнными IP-адресами.
6. Проверить сохранение правил `iptables` после перезагрузки.
7. Проверить открытые порты и убедиться, что лишние службы не слушают внешний интерфейс.
8. Повторно выполнить аудит безопасности.

Текущую SSH-сессию нельзя закрывать, пока вход по ключу и доступ к панели не проверены из отдельного соединения.

## Главное меню

### 1. Система

Раздел содержит диагностические операции:

- **Информация о системе** — показывает `/etc/os-release` и `hostnamectl`.
- **Все сервисы** — выводит загруженные службы `systemd` без интерактивного pager.
- **Системные логи** — запускает просмотр `/var/log/syslog` в реальном времени. Для выхода используется `Ctrl+C`.

Раздел не изменяет конфигурацию сервера.

### 2. SSH

#### Проверить SSH-настройки

Выводит эффективную конфигурацию через `sshd -T`, а не только строки из отдельных файлов. Проверяются:

- `PasswordAuthentication`;
- `PubkeyAuthentication`;
- `KbdInteractiveAuthentication`;
- `MaxAuthTries`;
- `PermitRootLogin`.

#### Заблокировать доступ по паролю

Операция:

1. Проверяет наличие непустого `authorized_keys` у текущего пользователя или `root`.
2. Создаёт резервную копию существующего файла.
3. Записывает `/etc/ssh/sshd_config.d/99-custom.conf`.
4. Отключает парольную и интерактивную авторизацию.
5. Ограничивает число попыток авторизации значением `5`.
6. Проверяет конфигурацию командой `sshd -t`.
7. Перечитывает конфигурацию SSH без остановки службы.
8. Автоматически возвращает предыдущий файл при ошибке проверки или перезагрузки.

После выполнения необходимо открыть второе SSH-соединение и проверить вход по ключу до закрытия текущей сессии.

#### Проверить отключение пароля

Проверяет, что эффективная конфигурация содержит:

```text
passwordauthentication no
```

Функция не пытается выполнить реальную авторизацию и не запрашивает пароль.

#### Найти настройки в SSH-конфигах

Показывает значимые директивы из основного файла и каталога `sshd_config.d`. Используется для поиска конфликтующих или переопределяющих настроек.

### 3. Fail2Ban

#### Установить Fail2Ban

Обновляет индекс APT, устанавливает пакет `fail2ban`, включает службу в автозагрузку и запускает её.

#### Показать статус

Доступны общий статус службы и состояние конкретного jail.

#### Настроить Fail2Ban

Создаёт управляемый файл:

```text
/etc/fail2ban/jail.d/99-server-setup.conf
```

Всегда включает jail `sshd`. Фильтры `nginx-botsearch` и `nginx-noscript` включаются только тогда, когда соответствующий фильтр установлен и существует журнал Nginx.

Перед применением выполняется `fail2ban-client -t`. При ошибке конфигурация откатывается. После перезапуска дополнительно проверяется активность службы.

Настройки по умолчанию:

- период наблюдения — 10 минут;
- блокировка — 1 час;
- допустимое число неудачных попыток — 5;
- локальные адреса исключены из блокировки.

#### Смотреть журнал

Запускает `tail -f /var/log/fail2ban.log`. Для выхода используется `Ctrl+C`.

### 4. Пользователи

Создаёт системного пользователя через `adduser`.

Перед запуском проверяется формат имени и отсутствие существующей учётной записи. Функция не добавляет пользователя в группу `sudo` автоматически.

### 5. Nginx

#### Показать статус

Выводит состояние службы без интерактивного pager.

#### Проверить и перечитать конфигурацию

Сначала выполняет:

```bash
sudo nginx -t
```

Только после успешной проверки выполняется `systemctl reload nginx`. Перезапуск процесса с разрывом соединений не используется.

### 6. Сеть

Показывает слушающие TCP- и UDP-порты, процессы и PID через:

```bash
sudo ss -lntup
```

Функция не изменяет сетевые настройки.

### 7. Фаервол iptables

#### Список правил

Показывает активные правила IPv4 с номерами строк.

#### Ограничить доступ к ISPmanager

Настраивает доступ к TCP-порту `1500`:

- создаёт управляемую IPv4-цепочку `ISPMGR_ACCESS`;
- разрешает указанные IPv4-адреса;
- отклоняет остальные IPv4-подключения к порту `1500`;
- создаёт цепочку `ISPMGR6_ACCESS` и закрывает порт по IPv6;
- сохраняет правила через `netfilter-persistent`;
- проверяет сохранённые правила командами `iptables-restore --test` и `ip6tables-restore --test`.

Перед любыми изменениями создаётся полная резервная копия активного фаервола. При ошибке изменения откатываются.

Если скрипт запущен по SSH, IP текущего подключения предлагается как значение по умолчанию. Это подсказка, а не гарантия: перед подтверждением адрес необходимо проверить вручную.

#### Показать доступ к ISPmanager

Показывает:

- IPv4 allowlist управляемой цепочки;
- прямые правила `INPUT` для порта `1500`;
- состояние IPv6-цепочки.

#### Добавить разрешённый IP

Добавляет IPv4-адрес перед завершающим правилом `DROP`, сохраняет конфигурацию и откатывает изменение при ошибке.

#### Удалить разрешённый IP

Удаляет адрес из управляемой цепочки и из поддерживаемого старого прямого правила. Скрипт запрещает удалять последний IPv4-адрес из allowlist.

#### Проверить сохранение правил

Показывает состояние `netfilter-persistent`, наличие файлов правил и проверяет возможность их восстановления без фактической перезагрузки фаервола.

### 8. Аудит безопасности без изменений

Собирает диагностический отчёт:

- версию ОС и ядра;
- эффективные настройки SSH;
- состояние SSH, Nginx, Fail2Ban, `netfilter-persistent` и FTP-сервера;
- открытые TCP- и UDP-порты;
- пользователей с UID `0`;
- пользователей с интерактивной оболочкой;
- участников группы `sudo`;
- состояние Fail2Ban;
- активную цепочку `INPUT`;
- доступные обновления пакетов.

Этот пункт не изменяет систему.

## Что скрипт намеренно не делает

- не меняет SSH-порт;
- не запрещает вход `root` автоматически;
- не добавляет нового пользователя в `sudo`;
- не включает автоматические обновления ОС;
- не настраивает общий фаервол для всех портов;
- не удаляет произвольные существующие правила `iptables`;
- не создаёт резервную копию всего VPS;
- не заменяет проверку внешнего доступа с другого компьютера.

Эти действия зависят от архитектуры конкретного сервера и не должны выполняться универсальным скриптом без отдельного решения.

## Проверка после изменений

После применения настроек рекомендуется проверить:

```bash
sudo sshd -t
sudo sshd -T | grep -E 'passwordauthentication|pubkeyauthentication|kbdinteractiveauthentication'
sudo fail2ban-client -t
sudo fail2ban-client status
sudo nginx -t
sudo ss -lntup
sudo iptables -L -n -v --line-numbers
sudo ip6tables -L -n -v --line-numbers
sudo iptables-restore --test /etc/iptables/rules.v4
sudo ip6tables-restore --test /etc/iptables/rules.v6
```

Самая важная практическая проверка — вход по SSH-ключу и доступ к ISPmanager с разрешённого IP в отдельной сессии.
